0. 一页看懂

V1 的结论是完整的负结果：DFD 测试 AUROC 0.4877、CelebDF++ 0.5284，区间都覆盖随机水平。 诊断排除了解码损坏、seek 保真度、学习率、特征坍缩、人脸检测器、身份数量， 留下的核心事实是：训练后的提取器在留出身份上的线性探针 ≈ 随机初始化。

V2 改四件有明确技术理由的事：

# 改动 解决什么
1 clip 长度 8 → 32 帧 旧设置时间感受野 7 已覆盖 8 帧中的 7 帧，没有剩余的时间结构可学
2 去掉时序建模之前的 temporal mean，改为 TCN → 时间聚合（GAP 起步，由 E4′ 选定） 旧结构在建模前就把时间顺序抹平
3 每步特征 15488 → 512（spatial_output_size 22→4） 让每个时间步能进 1D 卷积；贝叶斯头参数降两个数量级
4 贝叶斯头加非线性，512→256→64→1 旧头两层线性无激活，复合后等价于一层线性变换

准确地说，这套方案是"有监督表征学习 + 仅用真实视频的贝叶斯异常建模"：Phase A 用了 real/fake 标签，所以它不是端到端的单类（one-class）检测器（第 5 节）。

1. 远程机器评估（3080 Ti 12 GB / 32 GB 内存）

V1 在 batch=1、T=8 下跑，资源从来不是问题。V2 把 T 乘 4、batch 乘 4–8， 而 DFD 是 960×540 整帧——显存、主机内存、训练时长三样都要重新算。

测量方法：远程机器我连不上，所以在本地 GPU 上搭了与第 4 节完全相同的网络， 每个配置执行一次完整训练步（前向 + 反向 + Adam 更新），读 torch.cuda.max_memory_allocated。 显存占用由张量尺寸决定，与显卡型号基本无关，且对 batch 和 T 严格线性 （已验证：DFD 在 T=8/16/32 下分别为 0.69 / 1.36 / 2.69 GB），所以大 batch 的数值由 batch 1–2 的实测线性外推。 表中不含 CUDA context（约 0.4–0.5 GB）和分配器碎片，12 GB 卡的安全线按 10 GB 计。 脚本 vram_probe.py 在本文件夹，到远程后先跑一次核对。

1.2 主机内存

DataLoader 在 worker 里就把每帧转成 float32（data.py 的 normalize(to_tensor(...))）， 所以一个 clip 在主机内存里是：

单个 clip 训练一批 验证一项（4 clip） 评测一项（8 clip）
CelebDF++ 256×256 25 MB 8 clip = 0.2 GB 0.1 GB 0.2 GB
DFD 960×540 199 MB 4 clip = 0.8 GB 0.8 GB 1.6 GB

PyTorch 默认每个 worker 预取 2 批，所以排队中的数据 ≈ 2 × worker 数 × 每批大小。DFD：

worker 数 训练队列 评测队列（改后：1 视频/批） 评测队列（现有代码：4 视频/批）
2 3.2 GB 6.4 GB 25.5 GB ❌
4 6.4 GB 12.7 GB 51 GB ❌
8 12.7 GB 25.5 GB ❌ —

再加每个 worker 自身约 1 GB（V1 在 DFD 上实测每 worker 0.6–1.2 GB）和主进程 3–4 GB。结论：

  1. 评测改成 1 视频/批之后，DFD 用 4 个 worker 是安全的（≈ 12.7 + 4 + 4 ≈ 21 GB）。
  2. 推荐（非必须）：worker 只返回 uint8 张量，归一化挪到 GPU 上做。主机内存和 PCIe 传输都降为 1/4， 8 个 worker 也安全。改动只在 data.py 的最后一步和训练循环的第一步。
  3. 远程第一次跑时开着 free -g 看峰值；Linux 内存耗尽会直接杀掉进程，训练白跑。

唯一的实测参照：V1 的 DFD 整帧（T=8，也就是上表第二行）在租用机器上记录为约 10 分钟/epoch （每 epoch 2000 个 clip；当时的 GPU 型号没有记录）。E1–E4 的 DFD 计算量是它的 4 倍：

  • 若受 GPU 算力限制：约 40 分钟/epoch，60 epoch ≈ 40 小时/次，再加每 epoch 的验证。
  • 若受解码限制（1080p H.264、关键帧稀疏、每个 clip 要 seek）：取决于 worker 数，需实测。

CelebDF++ 的计算量是 DFD 的 1/8.6，视频又是 256×256 小文件，预计每次几个小时。

本地测得的单步耗时不作数：笔记本 GPU 在显存紧张时会慢一个数量级，同一配置两次测量相差 10 倍。 远程第一件事就是实测（第 7 节步骤 ①）：跑 scripts/benchmark_loader.py 测读取速度，再跑 E1-DFD 两个 epoch 计时， 同时看 nvidia-smi 的 GPU 利用率。

决策规则（DFD 单次训练预计超过约 24 小时时）：

现象 瓶颈 处理
GPU 利用率接近 100% 算力 DFD 启用 A12（conv1 stride 2），计算量降 4.1 倍，回到 V1 的量级
GPU 利用率低、CPU 满 解码 加 worker（需先做 uint8 改动）；stride 2 帮不上忙
两者都救不回来 — DFD 只跑 E0、E1、E4（E2、E3 的归因在 CelebDF++ 上完成）

2. 数据协议

2.1 本阶段采用 P0.5（开发协议）

协议 规则 用途
P0 视频级不相交；允许同一身份跨 split 仅作对照：量化"同源内容泄漏"会把分数抬高多少
P0.5 源视频家族不相交：一个真实视频和由它生成的所有伪造视频绑定在同一个 split；允许同一身份跨 split 本阶段全部实验
P1 身份不相交 + donor 规则（V1 用的协议） 扩充数据集后的正式实验

为什么不用 P1：数据量。DFD 在 P1 下训练只剩 20 个身份、val/test 各 4 个， donor 规则还要丢掉 36% 的 DFD 伪造视频和 27% 的 CelebDF++ 伪造视频。

为什么不用 P0：每个伪造视频都是从某一个真实视频生成的，和它共享背景、服装、光照和镜头运动。 CelebDF++ 里平均（中位数）84 个伪造视频共享同一个源视频（最多 244 个），DFD 是 9 个。 P0 按视频随机划分时，一个测试伪造视频的这些"兄弟"约 70% 落在训练集，模型可以靠记住背景拿分。

P0.5 的代价是零：

  • manifest 里已经有 source_clip 列，100% 的伪造视频都能对上它的源真实视频 （DFD 3,068 个、CelebDF++ 53,196 个全部匹配；三类伪造方法的命名都能解析）。
  • 每个视频恰好属于一个家族，一个视频都不丢。DFD 363 个家族（358 个带伪造视频）； CelebDF++ 890 个家族，其中 300 个 YouTube 真实视频没有伪造视频，各自单独成一个家族。
  • 仍然允许身份重叠：同一个人的其他视频、以及 donor 的脸，都可能出现在别的 split——这和放弃 P1 的初衷一致。

划分方法：按家族分层随机划分 70/15/15（CelebDF++ 的网络视频和 YouTube 视频分开分层），同一家族的所有 clip 都在同一个 split。

manifest 在本地生成、提交到仓库，远程只 git pull。README 已说明原因： 划分由扫描到的视频文件决定，远程少一个文件就会生成不同的划分，两台机器的结果从此不可比。

2.2 身份重叠的代价仍要先量化（E0S，不可跳过）

P0.5 去掉了同源内容泄漏，但身份重叠还在：测试集里某个人的脸，可能在训练集的其他视频里出现过； V1 那个后来作废的 0.7773，正是 donor 身份泄漏造成的。元数据捷径也仍然存在—— V1 严格协议测试集上，CelebDF++ 码率 0.783（方向调整后）、帧数 0.895、帧宽 0.924。

判据：后面任何模型分数，必须同时高于（a）随机初始化探针分布的上沿，（b）最强的单项元数据捷径。 达不到就不算"学到了东西"。

可选但推荐：在 CelebDF++ 上把 E0 在 P0 下再跑一次（只要几个小时），和 P0.5 的 E0 对比。 两者的差就是同源内容泄漏的大小——这是论文里说明"为什么不用 P0"的直接证据。

4. 模型架构

4.1 V1 → V2 到底改了哪里

Stage 1–3 的三层 3D 卷积逐层不变（通道 16→24→32、核 (3,5,5)、AvgPool (1,4,4)/(1,2,2)、BatchNorm3d、ReLU、全部 stride 1）。 改动全部在 stage 3 之后：

4.2 E4 主模型逐层

通道数 C 和时间步 T 在这里恰好都是 32，张量一律写成 [B, C, T, H, W]，读的时候注意第 2 维是通道、第 3 维是时间。

两个补充：

  • 空间压缩用 AdaptiveAvgPool3d((T, 4, 4))：指定输出尺寸，窗口自动计算，时间维原样通过。 CelebDF++ 的 26×26 → 4×4 时每格平均约 7×7 的区域。
  • 每个时间步被压缩了多少：CelebDF++ 从 32×26×26 = 21,632 压到 512（42 倍）， DFD 从 32×62×114 = 226,176 压到 512（442 倍）。V1 在这一步几乎不压（22×22）。 这一步会不会丢掉判别信息，正是 E2 → E3 要回答的问题。

4.3 DFD 的特殊问题：人脸只占一个池化格的四分之一

DFD 是整帧输入，伪造只发生在人脸上，而人脸在画面里很小。V1 实验 2 缓存了 2,326 个 DFD 视频的 dlib 人脸框， 中位宽 189 px（1920×1080），在送入网络的 960×540 帧里是 94 px：

人脸宽（960×540 中） 占画面面积 占一个 4×4 池化格 在 62×114 特征图上
最小的 10% 视频 66 px 0.8% 13% 约 8×8 个位置
中位 94 px 1.7% 28% 约 11×11 个位置
最大的 10% 视频 135 px 3.5% 56% 约 16×16 个位置

所以对 DFD 来说，问题不在 512 这个维度，也不主要在长宽比，而在"平均"把小面积的人脸信号和大面积的背景混在了一起。 把网格改成 4×7（A10）只能把人脸占比从 28% 提到 48%。

处理：在 E3-DFD 之前做一次不训练的池化筛查（6.2 节的实验 S）：取 DFD 最近一个已训练的检查点（E1 或 E2）， 对同一批 stage 3 特征图分别用 平均 4×4、最大值 4×4、平均 4×7、平均 8×14、平均 22×22（V1 参照）池化，各拟合一次线性探针。 若最大值 4×4 明显好于平均 4×4，DFD 的 E3、E4、E4′ 就改用 AdaptiveMaxPool3d((T,4,4))—— 维度仍是 512，TCN 和后面的部分完全不变。CelebDF++ 保持平均池化，人脸裁剪不存在稀释问题。 筛查只需要一次前向，不需要训练，代价很小。

筛查选中最大值池化也不等于最终结论：它对局部峰值敏感，既可能抓到人脸上的伪造痕迹，也可能抓到背景噪声或压缩块效应的峰值。所以改用之后，正式的 E3/E4 仍要对照 E0S 的元数据地板，并看训练曲线和特征方差是否稳定。

4.4 TCN

3D 卷积已经在时间上卷过了，为什么还要 TCN？ 有部分重叠，但层次不同： 3D 卷积在 125×125 这种高分辨率上、把时间和空间纠缠在同一个核里混合，每个输出只看 7 帧； TCN 作用在"整个画面的 512 维描述子"上，是纯时间操作，能表示 h[t] − h[t−1] 这样的帧间变化—— temporal mean 做不到，它对 [A,B,C,D] 和 [D,C,B,A] 给出相同结果。 如果 E4 相对 E3 没有提升，结论就是"7 帧的局部时序卷积已经够了"，这本身也是可以写进论文的发现。

参数量提醒：TCN 有 157.6 万参数，是提取器（9 万）的 17 倍。若 Phase A 明显过拟合，换瓶颈版 Conv1d(512→128, k1) → Conv1d(128→128, k3, d1) → Conv1d(128→128, k3, d2) → Conv1d(128→512, k1)，参数 230,272。

4.5 时间聚合：为什么主线用 GAP，为什么不直接 Flatten

你的问题：TCN 之后为什么一定要平均？不能保留 32 个时间步、直接 flatten 吗？

不是必须平均。 V2 的原则是"不能在时序建模之前平均"；时序建模之后怎样把 32 步汇总成一个向量， 是一个要用实验回答的问题。所以把它做成主线实验 E4′，紧跟在 E4 后面跑，GAP 只是起点。各变体的参数量从 0 到 839 万不等，所以选胜者要用多个 seed（6.2 节）。

聚合方式 做法 输出 聚合部分参数 依据
GAP（主线起点） 32 步取平均 [B,512] 0 LipForensics：MS-TCN 之后接时间全局平均池化
Max 每个通道取 32 步中的最大值 [B,512] 0 检验"伪造是否只是少数时刻的强异常"
Attention 小网络（512→128→1）给每步打分 αt，加权求和 [B,512] 65,793 让模型自己挑重要的时刻
Transformer CLS 1 层自注意力（8 头），取 CLS 输出 [B,512] 2,120,192 FTCN：时间 Transformer + class token
Flatten 32×512 拼成 16384，再 Linear 投影到 512 [B,512] 8,389,120 你的方案，作为对照
Flatten-小 每步先线性降到 64 维，32×64 拼成 2048，再投影到 512 [B,512] 1,081,920 参数受控的 Flatten：区分"Flatten 本身不好"和"只是参数太多"

Flatten 保留的信息确实最多，这一点没有争议。不作为主线的原因有三个：

  1. clip 的起点是随机采的。 同一个伪造痕迹，在这个 clip 里落在第 5 步，在下一个 clip 里可能落在第 21 步， "第 t 步"缺少稳定的含义。Flatten 后接线性层，等于 Σt Wt·ht，每个位置一套权重 Wt； 如果各位置的统计规律完全一样，最优解会接近所有 Wt 相等（也就是 GAP）。 但这个假设并不严格成立：clip 两端有卷积补零的边界效应，采样方式和视频剪辑规律也可能让不同位置的分布略有差别。 所以准确的说法是：Flatten 更容易学到"特定位置"的捷径，而且需要多得多的参数。
  2. 维度回到 V1。 16384 比 V1 的 15488 还大。不投影直接接贝叶斯头，第一层就是 16384×256 ≈ 419 万个权重、 839 万个变分参数，V2 好不容易解决的问题又回来了。所以对照组先投影到 512，投影本身就要 839 万参数。
  3. 担心"平均会稀释少数异常时刻"，有更直接的办法。 Max 和 Attention 正是针对这一点的，而且几乎不加参数； Transformer CLS 让所有时刻两两互看，是 FTCN 的做法。这三种都对"痕迹出现在第几步"不敏感。

你的担心由实验回答，而不是被默认。 E4′ 把 GAP 分别换成另外四种，其余完全不变：

  • Max / Attention / CLS 明显好于 GAP → 平均确实稀释了关键时刻，主线改用最好的那个；
  • Flatten 明显好于其余所有方式 → 位置相关的信息确实有用（可能来自边界效应或采样方式），值得深究；若 Flatten-小 也同样好，说明好处不只是来自参数多；
  • 都差不多 → TCN 已经把时间关系编码进了每一步的特征，平均不再损失有用信息。

4.6 Phase A 头：E0–E4 统一为单层 Linear

Linear(特征维, 1)：E0–E2 是 15488→1，E3–E4 是 512→1。V1 的 Stage A 头是 15488→512→1 且中间没有激活， 复合后本来就是一个线性函数，所以换成单层 Linear 不改变函数类，只是去掉了 793 万个多余参数。 头在 Phase A 结束后丢弃。

6.2 各步的判据

E0：只要能跑完并给出 P0.5 上的参照数字。若 E0 就冲到 0.85 以上，先去对照 E0S—— 极可能是身份泄漏或压缩捷径，不是模型变强了。

E1（clip 长度）：时间聚合还是 mean，预期变化不大。作用是在加 TCN 之前证明"加长 clip 本身不会变差"，并测出真实吞吐。

E2（batch）：batch=1 时 BatchNorm 的 batch 统计量就是单个视频自己的统计量—— 训练时相当于 instance norm，推断时却用跨视频的 running 统计量，两者不一致；而且每一步梯度只来自一个类别。 注意问题不在"样本少、统计不稳"（BN3d 在 T×H×W 上统计，单个视频也有大量元素），而在"只来自一个视频、一个类别"。 若 E2 明显好于 E1，说明 V1 的一部分失败要归到 batch=1。 DFD 的物理 batch 是 4（2 real + 2 fake），梯度累积 2 步；累积不改变 BN 看到的物理 batch，结果表里要注明。

S（DFD 池化筛查，E3 之前）：在同一个检查点上比较 5 种空间池化的探针 AUROC（再配 8 次随机初始化的分布）。若最大值 4×4 比平均 4×4 高出的部分超过随机初始化分布的波动范围，DFD 的 E3/E4/E4′ 改用最大值池化；否则保持平均。注意这个检查点是在 22×22 平均池化下训练的，筛查结果会偏向平均池化——所以最大值池化若仍然领先，结论反而更可信。

E3（512 瓶颈）：预期持平或略降，目的是给 E4 铺路。若明显下降，回退到 7×7（1568 维，加一层 Linear 到 512）。若只在 DFD 上明显下降而 CelebDF++ 没有，先看筛查结果：多半是人脸被稀释，而不是 512 维不够。

E4（主改动）：若相对 E3 没有提升，先查 TCN 是否退化：记录各层输出标准差和残差支路权重范数； 消融掉 d=2 那层看是否无差别。确认 TCN 在工作、仍无提升，才能下"时序建模没用"的结论。"TCN 有没有用"是全案最核心的结论，所以 E3 和 E4 在 CelebDF++ 上各跑 3 个 seed（E4 的三个 seed 与 E4′ 第二轮里的 GAP 共用），按 seed 均值和标准差比较，不看单次结果。

E4′（时间聚合）：各变体的参数量从 0 到 839 万不等，差的不只是聚合方式，还有模型容量；单次训练里 CLS 比 GAP 高 0.01，不能说明 CLS 更好。所以分两轮，都在 CelebDF++ 上做（每次只需几个小时）：

  1. 第一轮：五个变体各跑 1 个 seed（seed 42，与 E4 相同），按验证 AUROC 排出前两名。
  2. 第二轮：GAP 和前两名各补 2 个 seed（43、44），每种共 3 个 seed。
  3. 判定：某个变体的 3 个 seed 均值高于 GAP，且 3 个 seed 都赢（同一 seed 两两配对），且对三个 seed 的平均分数做配对 bootstrap，95% 区间不含 0——同时满足才定为主线聚合方式；否则保留 GAP（零参数优先）。

选出的方式用于 E5、E6（取它 seed 42 的检查点）和 E7。按 4.5 节的三种结果解读。选择只看验证集，测试集仍然封存。DFD 视时长，至少跑 Max——零参数，而且正好针对 DFD 的稀释问题。

E5 vs E6：按 5.3 节判读。

E7（上界对照）：回答论文绕不过去的问题——失败是架构的问题，还是"从随机初始化训 9 万参数"的问题？ 你们整理的文献表里，所有强结果都建立在预训练 backbone 上。两种结局都有价值： E7 也在 0.55 左右 → "这个协议下任务本身就难"；E7 到 0.85 → "从零训练的小提取器是瓶颈"。 E7 用 E4′ 选定的同一种聚合方式，这样 E4 与 E7 之间唯一的差别就是"从零训练 vs Kinetics 预训练"。因此 E7 要等 E4′ 选出结果后再跑。

E7b（可选）：MC3-18 冻结在 Kinetics 权重上，不做 Phase A，直接 32 步 → GAP → 探针和贝叶斯头。Kinetics 是动作识别的监督，不是 deepfake 的监督，所以这是方案里唯一整条流水线都没见过伪造标签的配置。论文若要主张单类或 data-agnostic，需要这个数字；它不训练提取器，只要前向和训练一个小头，代价很小。这里不用 TCN，因为 TCN 需要标签来训练。

9. 评价指标

9.1 AP 必须和 base rate 一起报

两个数据集在 P0.5 下都是伪造占多数。 按总量估算（实际值以步骤 ② 生成的 summary 为准，分层划分下各 split 应接近）：

数据集 总量 real / fake 以 fake 为正类的 base rate 以 real 为正类的 base rate
DFD 363 / 3,068 ≈ 0.89 ≈ 0.11
CelebDF++ 890 / 53,196 ≈ 0.98 ≈ 0.016

（第 5 版这里写的"DFD 验证集 45 real / 17 fake、base rate 0.27、两边不平衡方向相反"来自 V1 的 P1 划分，在 P0.5 下不再成立，已删除。）

现有代码 src/video_bcnn/metrics.py:93 以 fake 为正类。在伪造占多数时，这个 AP 几乎饱和： V1 的 CelebDF++ 测试集上 AP = 0.9733、base rate = 0.9698，只高 0.0035，信息量还不如 AUROC。

规定：

  1. 主指标是视频级 AUROC。
  2. AP 照报，但必须与 base rate 同行，并给出 AP − base rate；以 real 为正类再算一次 AP， 它的 base rate 很低（≈ 0.11 / 0.016），更能拉开差距。
  3. base rate 由 manifest 生成脚本输出，每次换划分都重算，不手抄。
  4. 不用 "mAP" 这个名字；两个数据集的 base rate 不同，平均 AP 没有意义。跨数据集汇总用 macro AUROC。

12. 已知的开放问题

  1. clip 级标签噪声：视频级的 "fake" 标签贴到 32 帧窗口上，窗口内可能没有可见篡改，这给 BCE 设了下限。 TalkingFace 尤其严重，它占 CelebDF++ 测试伪造视频的 78.8%。
  2. Leyva 原文 FC1 后有没有激活：旧代码的线性头来源无从考证。若原文有激活，V1 就是复现错误而不只是设计选择，需要回去查原文。
  3. 方案的叫法：见第 5 节。“单类 / data-agnostic”的主张目前只能由 E7b 支撑。

附录：相邻时间步的重叠，以及"跳步"该放在哪

三层 3D 卷积（时间核 3、stride 1）让输出第 t 步看输入的 t−3…t+3 共 7 步，相邻输出步共享其中 6 步。 重叠不是问题：空间上 5×5 stride 1 的卷积相邻输出也共享 80% 的窗口；重叠带来平移等变性—— 同一个瑕疵出现在第 10 帧还是第 11 帧，得到的是同样的响应、只是位置平移。 真正该看的是"感受野 / clip 长度"：V1 是 7/8 = 88%，V2 是 7/32 = 22%，相隔 7 步以上的输出完全不共享输入。

"跳步"的直觉有三个成立的落点，按优先级：

落点 做法 效果 对应
输入采样 从原视频每隔 s 帧取一帧 覆盖 32·s 帧的真实时长，网络内仍有 32 个时间步 A11，优先
TCN 内部 dilation 1、2（、4） 在高层描述子上扩大视野，不减时间步 主线已含，A1 扩展
提取器内部 时间 dilation (1,2,4)，或 stage 3 时间 stride 2 前者感受野 7→15；后者 T 32→16 省算力 A9、A8

不建议在 stage 1 设时间 stride：那是在语义信息最少的地方丢时间分辨率，deepfake 的线索常常只是一两帧的闪烁。 图 3画出了这三个杠杆在时间轴上的位置。
